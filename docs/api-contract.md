# API reference — Regional Museum Platform

This is the reference for the API **as implemented**. It began as the
contract frozen at Gate G2 (transcribed from the nine flow diagrams in
`docs/diagrams/`); where the built system differs, the change and its reason
are listed in [Changes from the G2 contract](#changes-from-the-g2-contract).

Live, always-current documentation of every request and response body is
generated by FastAPI at **`/docs`** (Swagger UI) and `/openapi.json` on any
running backend.

---

## Conventions

| Rule | Value |
|---|---|
| Prefix | every path starts with `/api` (except the `/health` liveness probe) |
| URL paths | `kebab-case` — `/api/collection-items`, `/api/membership-applications` |
| JSON fields | `snake_case` — `display_name`, `starts_at`, `price_cents` |
| Money | integer **cents** (`price_cents: 1500` = $15.00); never decimals |
| Times | ISO 8601 with offset, UTC from the server (`2026-11-07T23:30:00Z`); booking windows and opening hours are museum-local `"HH:MM"` |
| Content lookup | by `slug` (`/api/events/morse-code-galvanic-batteries`); events also accept the numeric id |
| Lists | `{ items, total, page, page_size }` for public content (collections, events, exhibitions); `{ items, total, page, size }` elsewhere; staff lists return `{ items, total }` (unpaged — small tables) |
| Errors | always `{ detail, code }`; a validation error (422) adds `fields: { field: message }` |
| Auth | `Authorization: Bearer <access_token>` from `POST /api/auth/login`; no refresh token — on 401 the front end returns the user to sign-in |
| Roles | checked **server-side** from the database on every request (never from the token): see `docs/role-permission-matrix.md` |

Role scopes below: **Public** (no token) · **Signed in** (any account) ·
**Member+** (member, staff, admin) · **Staff** (staff, admin) · **Admin**.

## Accounts

| Method | Path | Role | Notes |
|---|---|---|---|
| POST | `/api/auth/register` | Public | `{email, password (≥8), first_name, last_name}` → 201 user; 409 `CONFLICT` if the email is taken. New accounts are Visitors. |
| POST | `/api/auth/login` | Public | `{email, password}` → `{access_token, token_type, user}`; 401 `AUTH_INVALID`; 403 `ACCOUNT_DISABLED` |
| GET | `/api/auth/me` | Signed in | current user `{id, email, display_name, role}` |

## Collections, exhibitions, events (visitor-facing)

| Method | Path | Role | Notes |
|---|---|---|---|
| GET | `/api/collection-items` | Public | `?q=&gallery=&category=&year_from=&year_to=&family_friendly=&highlight=&page=&page_size=` — published objects only |
| GET | `/api/collection-items/{slug}` | Public | object with its `exhibition`; 404 for unknown or draft |
| GET | `/api/exhibitions` | Public | `?q=&gallery=&page=&page_size=` — published, not yet closed; `phase` = current / upcoming |
| GET | `/api/exhibitions/{slug}` | Public | exhibition with its published `items` |
| GET | `/api/events` | Public | `?q=&gallery=&audience=families|adults&from=&to=&page=&page_size=` (contract `size`, `tag` also accepted). Drafts never listed. Each event has `spots_remaining`, `is_sold_out`, `is_past`, `status` (published / cancelled / completed) |
| GET | `/api/events/{slug or id}` | Public | 404 for unknown or draft |
| POST | `/api/events/{slug}/registrations` | Signed in | `{contact_name, contact_email, party_size 1–10}` → 201 `{reference, status, …}`; 409 `EVENT_FULL`, `ALREADY_REGISTERED`, `REGISTRATION_CLOSED` |
| GET | `/api/event-registrations/me` | Signed in | own registrations |
| POST | `/api/event-registrations/{reference}/cancel` | Signed in | own, upcoming only; frees the places; 409 otherwise |

## Visiting and booking

| Method | Path | Role | Notes |
|---|---|---|---|
| GET | `/api/opening-hours` | Public | `{weekly: [7 days, Sunday = 0], overrides: [dated exceptions from today]}` |
| GET | `/api/visitor-information` | Public | address, transport, parking, contact, about, `facilities[]` |
| GET | `/api/ticket-types` | Public (richer when signed in) | prices in cents; the Member ticket only for an active membership, with `max_quantity` = people covered |
| GET | `/api/bookings/availability?date=YYYY-MM-DD` | Public | `{is_closed, opens_at, closes_at, note, windows: [{start, end, places_left}]}` — two-hour windows, 60 places each, 60 days ahead |
| POST | `/api/bookings` | Signed in | `{visit_date, arrival_window: {start}, lines: [{ticket_type_id, quantity}], visitor, accessibility[], payment_acknowledged: true}` → 201 booking with `reference`; 400 `INSUFFICIENT_TICKETS`; 409 `BOOKING_LIMIT_EXCEEDED` (>10 tickets); 403 Member ticket without membership. **Payment is simulated.** |
| GET | `/api/bookings/me` | Signed in | own bookings, newest visit first |
| GET | `/api/bookings/{reference}` | Signed in | own booking (staff: any); someone else's → **404** |
| POST | `/api/bookings/{reference}/cancel` | Signed in | own, `reserved` only; 409 otherwise |

## Membership and the member portal

| Method | Path | Role | Notes |
|---|---|---|---|
| GET | `/api/membership-plans` | Public | Individual $65 · Family $120 (2 adults + up to 3 children) · Patron $280 |
| POST | `/api/membership-applications` | Visitor / member account | `{plan_id, children_covered}` → pending record; 409 `MEMBERSHIP_ACTIVE` if one is active or pending; 403 for staff/admin accounts |
| GET | `/api/memberships/me` | Signed in | current record or 404 |
| GET | `/api/activity/me` | Signed in | own activity, incl. decisions about you |
| GET | `/api/interest-tags` | Public | the eight interests |
| GET / PUT | `/api/me/interests` | Signed in | `{tags: [slug]}` |
| GET | `/api/recommendations?type=&size=` | Member+ | ranked, each with `matched_tags` and `reason`; visitor account → 403 `FORBIDDEN` |

## Staff workspace (Staff)

| Method | Path | Notes |
|---|---|---|
| GET / POST | `/api/staff/collection-items` | list incl. drafts; create (draft needs only a title; publishing needs accession number, description, category, gallery); 409 `ACCESSION_TAKEN` |
| PATCH / DELETE | `/api/staff/collection-items/{id}` | publishing is a PATCH of `status`; `tags` replaces interest tags |
| GET / POST | `/api/staff/exhibitions` | |
| PATCH / DELETE | `/api/staff/exhibitions/{id}` | delete refused with 409 `EXHIBITION_HAS_ITEMS` while objects are attached |
| GET / POST | `/api/staff/events` | create with `starts_at`, `ends_at` (same local day), `capacity`, prices, ages, `status` |
| PATCH / DELETE | `/api/staff/events/{id}` | 409 `CAPACITY_BELOW_REGISTRATIONS`; delete refused with 409 `EVENT_HAS_REGISTRATIONS` (cancel instead) |
| GET | `/api/staff/events/{id}/registrations` | who is coming |
| PUT | `/api/staff/opening-hours` | `{weekly: [7], overrides: [...]}`; 422 `INVALID_HOURS` |
| PUT | `/api/staff/visitor-information` | whole page incl. facilities |
| GET | `/api/staff/bookings?date=&q=` | every account's bookings |
| GET | `/api/staff/bookings/summary?date=` | bookings / tickets / checked in per window |
| POST | `/api/staff/bookings/{reference}/check-in` | 409 `NOT_TODAY`, `ALREADY_CHECKED_IN` |
| POST | `/api/staff/bookings/{reference}/cancel` | on a visitor's behalf |
| GET | `/api/staff/today` | dashboard figures |
| POST / GET | `/api/staff/{collection-items\|exhibitions\|events}/{id}/media` | upload (multipart `file`, `is_primary`, `sort_order`) / list; 413 `FILE_TOO_LARGE`, 502 `STORAGE_ERROR` — see `docs/design/media-storage.md` |
| DELETE | `/api/staff/media/{media_id}` | |

## Administration (Admin)

| Method | Path | Notes |
|---|---|---|
| GET | `/api/admin/members?q=&status=&tier=` | `{items, total, counts}` for the Members screen |
| POST | `/api/admin/members/{id}/approve` | pending → active; grants the Member role |
| POST | `/api/admin/members/{id}/decline` | optional `{reason}` |
| POST | `/api/admin/members/{id}/revoke` | **reason required** (422 `REASON_REQUIRED`); disables the account |
| POST | `/api/admin/members/{id}/restore` | re-enables, fresh period if expired |
| GET | `/api/membership-applications?status=` | contract (Flow 6) list; `…/{id}/approve` and `…/{id}/reject` as above |
| GET | `/api/users?q=&role=` | accounts with role and `is_active` |
| PATCH | `/api/users/{id}` | `{role}` and/or `{is_active}`; your own account → 409 `CANNOT_MODIFY_SELF` |
| GET | `/api/admin/activity-log?q=&action=` | audit log, newest first |

Every staff and admin change, and every booking, registration, application
and admin decision, is written to the activity log by the server.

## Health

| Path | Meaning |
|---|---|
| `GET /health` | liveness (no database) — used by Render and Compose |
| `GET /api/health` | readiness — 503 if the database doesn't answer within 2 s |

## Error codes

| Code | Status | Meaning |
|---|---|---|
| `VALIDATION_ERROR` | 400 / 422 | input rejected; 422 adds `fields` |
| `AUTH_REQUIRED` / `AUTH_INVALID` | 401 | no token / bad or expired token or credentials |
| `ACCOUNT_DISABLED` | 403 | account revoked or disabled |
| `FORBIDDEN` | 403 | signed in without the required role |
| `NOT_FOUND` | 404 | unknown, draft, or someone else's record |
| `CONFLICT`, `MEMBERSHIP_ACTIVE`, `ALREADY_REGISTERED`, `EVENT_FULL`, `REGISTRATION_CLOSED`, `BOOKING_LIMIT_EXCEEDED`, `ACCESSION_TAKEN`, `EXHIBITION_HAS_ITEMS`, `EVENT_HAS_REGISTRATIONS`, `CAPACITY_BELOW_REGISTRATIONS`, `NOT_TODAY`, `ALREADY_CHECKED_IN`, `CANNOT_MODIFY_SELF` | 409 | refused for a business reason |
| `INSUFFICIENT_TICKETS` | 400 | not enough places left in that arrival window |
| `INVALID_HOURS`, `REASON_REQUIRED` | 422 | |
| `FILE_TOO_LARGE` | 413 | |
| `STORAGE_ERROR` | 502 | media backend unavailable |
| `INTERNAL_ERROR` | 500 | unexpected; details only in the server log |

## Changes from the G2 contract

| Area | G2 contract | Implemented | Why |
|---|---|---|---|
| Collections | `/api/collections`, numeric id, `size` | `/api/collection-items`, slug, `page_size`, richer fields | The front end was built and usability-ready against this shape; changing the documented shape was cheaper than rebuilding pages (decision log, 2026-10-23) |
| Events | `display_name`, `event_time` only | front-end fields (`title`, `starts_at`, `ends_at`, capacity, prices, ages) **plus** the contract's fields | Pages need capacity and prices; contract clients keep working |
| Event registration | `POST /api/events/{id}/register {quantity}` | `POST /api/events/{slug}/registrations {contact_name, contact_email, party_size}` | Registration records who is attending, as staff need for the session |
| Ticket booking | per-event `POST /api/events/{id}/bookings` | general admission `POST /api/bookings` with date, arrival window and ticket lines | The client asked for "tickets online for general admission"; schema and screens model admission by date (decision log, 2026-10-11) |
| Staff content | `POST /api/exhibitions` etc. | `/api/staff/exhibitions`, `/api/staff/collection-items`, `/api/staff/events`, PATCH for updates | A separate `/api/staff` prefix makes the role boundary visible and lets the role check sit on the router |
| Opening hours / visitor info writes | `PUT /api/opening-hours`, `PUT /api/visitor-information` | `PUT /api/staff/…` | Same reason |
| Admin users | `access_status` field | `is_active` only | `access_status` restated `is_active` |
| Errors | `{detail, code}` | unchanged; validation adds `fields` | |
| Added | — | recommendations interests, activity log, staff bookings and check-in, staff today, visitor information, media | Requirements 3(iv), the role matrix and booking management |
